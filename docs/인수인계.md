### relaxed_deadline 분석 요약 (수정 후)

| | Greedy | CPR 최고 (0.35, 0.15, 0.50) |
|---|---|---|
| 지연 건수 | 0 | 0 |
| makespan | 17463 | 17339 (−0.7%) |
| 단편화 감소율 | 22.7% | 92.2% |
| 총 이동거리 | 111,660 | 91,638 (−17.9%) |
| 디스패치 수 | 1,165 | 1,220 |

- 버그 수정 효과: 지연 0건인 조합 172개 → 194개 (전체 231개), 평균 makespan −170초
- α3 = 0이면 크게 나빠짐 (평균 지연 4.9건, 이동거리 +25%). α2는 0.10~0.25가 좋음. α1이 0.8 이상이면 단편화 감소율이 무너짐 (α1 = 1.0이면 22%로 Greedy 수준)
- **상위 조합끼리 목적함수 차이가 매우 작다.** 상위 15개가 1% 이내, 수정 전후 순위 상관(Spearman) 0.73. 최적값 하나보다 **범위**(α2 0.10~0.30, α3 0.10~0.55)로 보고해야 함
- **목적함수에서 단편화 항이 사실상 작동하지 않는다.** F̂ 값 자체가 0.002~0.05로 작아서, 가중치 0.3을 줘도 Z 기여가 1.5%뿐. Z는 사실상 makespan + 거리로 순위를 매기고 있음
- relaxed_deadline은 납기가 느슨해서 S_T(긴급도)의 역할을 판단할 수 없다. 납기가 빡빡한 시나리오가 필요

## 3. 합의된 결정 사항

### 연구 범위
- 소형 전자제품 **main / sub 조립 라인** 키팅. SMD(릴 부품)는 제외
- **라인 간 선후관계(sub → main)는 반영하지 않는다**

### 목적함수 Z
- **makespan 항은 B안**: 시나리오(인스턴스)마다 Greedy makespan을 고정 기준값으로 쓴다. Greedy는 경쟁 상대가 아니라 같은 자(ruler)로 쓰이므로 모든 방법이 같은 기준으로 평가된다
- 검토 후 기각한 안
  - 마지막 납기로 나누기: 납기가 아주 느슨하면 makespan 항의 실제 비중이 작아짐
  - 그리드 내 최고값(`M_best`)으로 나누기: 정책 하나만 평가하거나 GA 적합도 계산 시 쓸 수 없음
- 최종 평가에서는 Z와 함께 **각 지표의 원래 값**을 보고하고, 여러 인스턴스를 정리할 때는 RPD(최고값 대비 편차 %)를 보조로 쓴다

### 단편화 지표 방향 (아직 구현 안 됨)
- 현재 F̂(`metrics.calc_fragmentation_index`)는 단편화보다 **용적 활용률**에 가깝다. 같은 부품이 얼마나 흩어져 있는지는 재지 않는다
- 새 지표 방향
  1. **종료 시점**: 꺼냈다가 잔량을 남긴 토트 수. **한 번도 안 꺼낸 토트는 단편화가 아니다** (원래 상태로 돌아가는 가장 좋은 잔량)
  2. **진행 중**: 재방문 비율 `(디스패치 수 − 사용한 토트 수) / 사용한 토트 수`
- 측정값 (relaxed_deadline)

| | 꺼냈다가 잔량 남긴 토트 | 안 꺼낸 토트 | 재방문 비율 |
|---|---|---|---|
| Greedy | 66 | 73 | 0.300 |
| CPR (0.35, 0.15, 0.50) | 21 | 8 | 0.270 |
| CPR (0.30, 0.35, 0.35) | - | 10 | 0.261 |

- 참고: 거리 지표 D̂는 디스패치당 평균이라 재방문을 벌점으로 주지 않는다

### 토트 할당과 잔량
- 회사는 **전체 부품 필요량을 채우는 토트 세트**를 고른다 (FIFO, 오래된 재고부터). 운이 좋으면 모두 비고, 아니면 잔량이 남는다
- **일부러 두는 여유율(N%)은 두지 않는다.** 잔량은 자연스럽게 생기는 것만 둔다
  1. 카톤 단위 입고 올림: `입고 수량 = ⌈필요량 / Lot⌉ × Lot`
  2. 이전 잔량 토트에 딸려 오는, 오늘 필요 없는 부품

### 혼합 토트가 생기는 이유 (현장 기준, 합의됨)
1. 부피가 큰 SKU: 토트에 카톤 1개만 들어가고 남는 공간에 다른 SKU를 넣음
2. 단일 SKU 입고 후 남은 자투리 카톤을 모아 한 토트에 넣음
3. 이전 키팅 후 남은 잔량 토트에 다른 SKU를 채워 넣음

- 이커머스의 mixed-shelves / 분산 보관 논리는 키팅에 적용되지 않는다 (pod 하나가 주문 여러 개를 처리하는 구조와 달리, 키팅은 토트 수십 개가 키트 하나를 채움)
- 악순환 구조: 키팅 단편화 → 빈 토트 부족 → 혼합 입고 증가 → 다음 키팅 단편화 증가. 논문의 동기로 활용 가능

## 4. 데이터셋 재설계 계획 (`data/dataset_generator3.py`, 미착수)

기존 `dataset_generator2.py`는 재현성을 위해 그대로 둔다.

### 지금 데이터의 한계
- SKU 10종, 모델 5종, 모델당 부품 4종. 라인 하나에 모델 하나 고정
- 모든 부품이 키트당 토트 2~7개 분량이 필요하고, 카톤이 토트당 4~7개 들어감. 큰 SKU가 없음
- 그래서 혼합 토트 38%의 현실적 근거가 없음 (무작위로 2~4개 부품을 섞어 생성)

### 생성기 설계안
1. **BOM과 생산 계획을 파라미터로 생성**: 공용 부품과 모델 전용 부품, 롱테일 사용량 분포, 라인마다 하루 여러 번 모델 교체
2. **입고 규칙 기반 토트 생성**
   - 큰 SKU (카톤 부피 > 토트의 절반): 토트당 카톤 1개, 남는 공간은 채움 후보
   - 그 외 SKU: 꽉 찬 단일 토트 + 자투리 카톤
   - 자투리 카톤 배치 순서 (**미확정**): (a) 이전 잔량 토트 → (b) 큰 SKU 토트의 남는 공간 → (c) 새 토트 (큰 카톤부터)
3. **이전 잔량 토트**: 비율을 파라미터로 두고, 안에 든 부품은 전체 SKU에서 무작위로 뽑는 것을 기본값으로 함
4. 시드로 여러 인스턴스 생성

### 규모 기본값 제안 (회사 감각으로 확인 필요)

| 파라미터 | 소 | **중 (기본)** | 대 |
|---|---|---|---|
| 하루 키팅 SKU 수 | 30 | **80** | 200 |
| 모델 수 | 5 | **12** | 30 |
| 모델당 부품 종류 | 10 | **20** | 35 |
| 공용 부품 비율 | 20% | **30%** | 40% |
| 라인 수 (main / sub) | 2 / 2 | **3 / 3** | 5 / 5 |
| 라인당 하루 모델 교체 | 2 | **4** | 6 |
| 큰 SKU 비율 | 10% | **15%** | 20% |
| 이전 잔량 토트 비율 | 0% | **5%** | 10% |

- 이 문제에 바로 쓸 수 있는 공개 벤치마크는 없다. "생성기 공개 + 요인 수준 실험 + 사례 기업 데이터로 기본값 설정"이 표준적인 방법
- 규모를 키운 뒤 시뮬레이션 1회 실행 시간을 먼저 재서 그리드 서치가 가능한지 확인
